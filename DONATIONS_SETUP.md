# Донатные заказы в TwitchTune

Открой **04 Настройки → ДОНАТЫ / ЗАКАЗЫ БЕЗ ОЧЕРЕДИ**.

## DonationAlerts

1. Войди в свой аккаунт DonationAlerts и открой [регистрацию приложений](https://www.donationalerts.com/application/clients).
2. Создай приложение, например AcidDeckMusic. Укажи точный Redirect URI:
   `http://127.0.0.1:8765/callback`
3. Скопируй **Client ID** в поле DonationAlerts в TwitchTune.
4. Нажми **Войти в DonationAlerts**. В браузере войди в нужный аккаунт и разреши чтение профиля, чтение и получение донатов.
5. Когда браузер сообщит о завершении, вернись в TwitchTune. Дождись статуса **Подключено · имя канала**.

Client Secret не нужен для используемого публичного входа. Client ID можно использовать в копии приложения другого человека, но каждый входит в свой аккаунт. Если вход истечёт, снова нажми кнопку входа. Если порт8765 занят, закрой другое окно входа/экземпляр приложения и повтори.

## DonateX

1. Открой кабинет DonateX → **Настройки → API и доступ**.
2. Скопируй **External token**.
3. Вставь его в поле DonateX внутри TwitchTune и нажми **Подключить DonateX**.
4. Дождись **Подключено · имя канала**. Поле токена очистится после подключения.

Токен вводится только в приложение, в поле с паролем. Вход хранится в системном хранилище Windows; настройки JSON содержат только Client ID/флаги подключения. После перезапуска сервисы подключаются автоматически, если вход сохранён. Если хранилище недоступно, сообщение об этом появляется в журнале: текущий сеанс работает, после закрытия потребуется подключиться снова.

## Как заказывать музыку

- Зритель отправляет донат с одной или несколькими поддерживаемыми ссылками в сообщении. DonateX также поддерживает отдельное поле заказа музыки `musicLink`: если оно заполнено, ссылки берутся из него.
- Заявка автоматически сохраняется, скачивается и встаёт перед VIP и обычными заказами. Играющая или поставленная на паузу песня не прерывается.
- Несколько донатов идут в порядке времени поступления, независимо от суммы. В очереди видны ник, сервис, сумма и валюта.
- Донатным файлам отдаётся приоритет перед обычными ожидающими загрузками. Уже выполняющиеся загрузки завершаются. Если следующий донат ещё загружается, автоматическое воспроизведение ждёт его готовности; при явной ошибке загрузки остальные готовые заявки могут продолжить играть.
- Все обычные возможности сохранены: оценка11–66, тексты, история после оценки, ручной повтор загрузки и выбор версии. Лимит для донатного трека — 90минут и512МБ; сумма доната его не меняет.
- Ссылка на поддерживаемый альбом добавляет одну приоритетную заявку с общей оценкой, а песни хранятся в папке альбома. Длительность ограничена90минутами на каждую песню.
- Сообщения без поддерживаемых ссылок или с пометкой «в тг» не создают заказ. Неподдерживаемые и повторные одинаковые ссылки пропускаются. DonateX-события, отмеченные модерацией как небезопасные, пропускаются.
- При заполненной очереди заказ остаётся во входящих, их число видно в настройках. Через две секунды после освобождения места программа попробует добавить его снова. Ошибка чтения альбома повторяется с паузой в минуту.

## Расценки

В **04 Настройки → ДОНАТЫ → Расценки на донатные треки** задай стоимость одного трека в рублях (целое число от1 до1000000). По умолчанию200 ₽. Настройка сохраняется автоматически и действует для DonationAlerts, DonateX и ручного выбора сообщений из истории. Рядом автоматически показаны суммы для1,2,3 и5 треков.

| Донат при цене200 ₽ | Максимум песен |
| --- | --- |
| Меньше200 ₽ | Пропуск |
| 200–399,99 ₽ | 1 |
| 400–599,99 ₽ | 2 |
| 600–799,99 ₽ | 3 |

Доступное число песен — целая часть суммы, делённой на цену. Ссылки принимаются по порядку в сообщении в пределах оплаты. Если ссылок меньше, повторы не создаются; остаток не переносится между донатами. Несколько отдельных донатов не суммируются. Поддерживается валютаRUB; другая валюта пропускается, автоматического пересчёта нет. Минимум действует и для тестовых событий, поэтому тест должен содержать сумму от установленной цены.

Альбом стоит по числу песен:5треков ×200 ₽ =1000 ₽. Сначала программа читает список песен, затем принимает альбом целиком, если хватает оплаты. При недостаточной сумме альбом целиком пропускается; следующие отдельные ссылки в том же сообщении могут использовать оставшийся бюджет. Ошибка получения состава альбома повторяется через минуту без повторного начисления оплаты.

Цена фиксируется в момент приёма доната. Уже принятые заказы и прежняя очередь не пересчитываются при изменении настройки. Пропущенные донаты ниже минимума также помечаются обработанными: повторная доставка после смены цены не создаёт заказ. Журнал показывает причину пропуска или число принятых песен. Подтверждение суммы берётся из события сервиса; приложение не выполняет возвраты платежей.

## Проверка

1. Подключи нужный сервис и дождись «Подключено».
2. Для DonateX временно включи **Принимать тестовые донаты DonateX** и отправь тест из кабинета со ссылкой в сообщении или поле музыки. После проверки отключи флажок.
3. В DonationAlerts добавь сообщение со ссылкой через «Мои сообщения → Добавить сообщение». После первого подключения дождись строки «История проверена», затем создай новое сообщение и подожди 10–15 секунд. Доставка через живые события зависит от сервиса; TwitchTune дополнительно проверяет историю API каждые 10 секунд. Новые ID обнаруживаются даже с вручную указанной прошлой датой, если сообщение находится на проверяемых страницах.
4. В очереди появится одна заявка перед обычными; играющая песня продолжится. Повтор одного события не создаёт новую запись.

### Если сообщение уже добавлено, но его нет в очереди

В настройках DonationAlerts нажми **Сообщения из кабинета…**. Программа прочитает первую страницу API (до30 сообщений) и покажет ВСЕ полученные записи. У сообщений с подходящими ссылками и суммой не ниже текущей цены вRUB доступны флажки. У остальных в колонке «Результат проверки» указана причина пропуска. Отметь нужные строки и нажми **Добавить выбранные**. Для этого пути дата сообщения не ограничена временем запуска. Старые сообщения сами по себе массово не импортируются; уже принятые или удалённые заказы повторно не добавляются. Окончательная проверка цены альбома выполняется после чтения списка его песен.

Если API вернул сообщения, а подходящих0, выбери нужную строку. В нижнем поле появятся полный текст, точная причина и основные поля API (тип события, сумма/валюта, флаги теста/модерации). Это поле можно скопировать или прислать его скриншот. Токены и заголовки авторизации в него не попадают. В живом соединении причины отказа также записываются в журнал, без постоянного повторения одной причины для одногоID.

В окне указано, сколько сообщений вернул сервис и сколько подходит для заказа по ссылкам и цене. Если нужной строки вообще нет, сервис не вернул её на первой странице API. Наличие записи в кабинете не гарантирует её доступность через публичный API. В таком случае ту же ссылку можно вставить в основную очередь вручную. Ошибка доступа к истории требует повторного входа с правом чтения донатов.

При удалении заказа его повторная доставка не восстанавливает песню. Повторное прослушивание из истории не расходует донат и не возвращает ему приоритет автоматически. Ники донатеров показываются с сервисом в профилях и не связываются автоматически с подтверждённой учётной записью Twitch.

## Обрывы и перезапуск

Живые события поступают через WebSocket. DonationAlerts также сверяет историю каждые10секунд, даже при недоступности WebSocket после успешного чтения профиля. Первая проверка запоминает ID первой страницы и автоматически принимает только сообщения с датой не раньше запуска подключения; старые доступны через ручной выбор. Следующие проверки принимают новые ID независимо от даты и читают до10страниц (до300 сообщений), останавливаясь на странице с известным ID. Сильно задним числом вставленная запись за пределами этих страниц может потребовать ручного добавления. Строка в настройках показывает последнюю успешную проверку или ошибку. Ограничение API учитывается, после429 выдерживается пауза.

DonateX не опрашивается по таймеру: его история проверяется только после подключения/переподключения за текущий сеанс, максимум10страниц (до1000 сообщений). При большом объёме или ошибке восстановления сообщение появляется в журнале. Получение одного заказа разными путями не создаёт дублей благодаря постоянному ключу сервис/аккаунт/ID.

Старые донаты до запуска текущего сеанса автоматически не импортируются при первом снимке истории. Уже полученные заказы и ожидающие добавления сохраняются в базе и переживают перезапуск. Пропущенные во время закрытого приложения сообщения DonationAlerts можно выбрать вручную. Отключение сервиса прекращает получение новых событий и проверку истории, уже принятые заказы остаются.

## Источники и проверка реализации

- [DonationAlerts API](https://www.donationalerts.com/apidoc): OAuth Implicit, профиль, Centrifugo, история.
- [DonateX: авторизация](https://donatex.gg/api-docs/authentication).
- [DonateX: realtime](https://donatex.gg/api-docs/realtime).
- [DonateX: донаты](https://donatex.gg/api-docs/donations).

Реализация проверена офлайн, включая форматы протоколов и авторизацию через локальный callback с проверкой state. Вход и получение оплаченного события на реальных аккаунтах требуют проверки после подключения владельцем. Готовый Windows EXE здесь не собирался: после замены исходников выполни build_exe.bat. Отправляя готовую сборку, передавай всю папку dist/TwitchTune; получателю достаточно запустить TwitchTune.exe и подключить свои сервисы.


## Если было «Тип события: Donations (ожидался donation)»

Это ошибка прежнего фильтра TwitchTune. Обнови исходники, выполни build_exe.bat и запусти новую сборку. DonationAlerts теперь поддерживает оба варианта donation и Donations. В истории нужные строки получат флажки: отметь их и нажми «Добавить выбранные». Новые донаты с этим типом обрабатываются автоматически через события/автопроверку истории. Цена и остальные правила не меняются.


## Если уже используешь быстрый запуск

Для обновлений через новый ярлык TwitchTune или небольшой установщик build_exe.bat не нужен. Требования сборки в прежних разделах относятся к EXE. После обновления запускай новый ярлык TwitchTune, а не прежний EXE изdist. См. QUICK_START.md.
